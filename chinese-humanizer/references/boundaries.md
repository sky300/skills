# 边界：什么不该改

去 AI 味最常见的失败不是改得不够，是改过头：把术语改成同义词、把引语改口语、把正式文体改成聊天、把作者的习惯当成 bug。改之前先看这份清单。

## 一、绝对不动

- **引号里的引语**。一个字都不改。要质疑的是引语周边的叙述，不是引语本身。
- **代码、命令、路径、文件名、配置项、YAML、链接目标**。只改散文。
- **数字、公式、引用编号、cite key**。不四舍五入，不改格式。
- **术语与专名**。同一概念全篇用同一个词，不要为了避免重复而轮换同义词。
- **标题**（除非用户点名要改）。标题有自己的语法，不按正文规则改。
- **讨论某个词本身的段落**。文中正在分析「赋能」这个词时，不能顺手把它改掉。

## 二、要看体裁

同一句话在不同文体里的判断相反。改之前先确认目标文体。

| 体裁 | 默认处理 | 必须保留 |
| --- | --- | --- |
| 博客 / 随笔 | 保留观点、犹豫、幽默、口语词 | 作者的语气、个人经历、具体细节 |
| 技术文档 / README | 中性、直白，删套话与宣传腔 | 术语、参数、命令、版本号、接口名 |
| 学术 / 报告 | 只削过度断言与意义炒作 | hedging、被动、第一人称复数、分号、术语符号、论断与证据的对应关系 |
| 公文 / 法律 | 基本不改，只删重复与空转 | 固定表述、条款结构、范围限定 |
| 营销 / 品牌 | 提高修辞阈值，只查事实越界 | slogan、留白、节奏、称呼方式 |
| 自媒体 / 社媒 | 允许口语与不规范表达 | 作者既有的口头习惯 |

技术文档被人改成聊天口吻、学术文字被人情味稀释，都是这个 skill 用错方向。

## 三、容易误改的地方

- **正式不等于 AI**。用词正式、语法完美、风格统一都不是证据。
- **单个词不是证据**。「值得注意的是」出现一次、破折号用了一次，都不构成问题。
- **hedging 是证据的一部分**。「可能与…相关」在学术文本里是准确，不是懦弱。
- **被动句有时是必需的**。受事或责任需要明确时，被动比硬改主动更准确。
- **「的地得」、错别字、标点全半角**属于校对范畴，不在这个 skill 的处理范围，除非用户明确要求。
- **人写的中文本来就有翻译腔**。译者和双语写作者的习惯不该被当成 AI 痕迹。
- **平台检测的结果不是判据**。见 `evidence.md` 第四节。

## 四、不要为了「有人味」硬加东西

- 不加第一人称、不加幽默、不加感叹、不加情绪词。声口要来自作者本人，不来自模板。
- 不编造细节、人名、经历、场景、数据来「增加具体性」。缺细节就问，或者删掉那句。
- 不制造错别字、语病、口头语来「显得像人」。这是另一种假。
- 不把段落打乱、把句子写碎来伪造「不规则」。乱不等于自然。
- 不为破三连删掉本来独立的例子。三个独立故障、三个独立步骤都要留着。

## 五、需要作者确认的情况

遇到下面这些，不要静默处理，单列清单请作者决定：

- 原文的因果关系、比较关系、因果词没有依据（时间先后写成了因果、不同尺度拿来比较）
- 原文的论断强度与证据不匹配（相关写成因果、观察写成证明）
- 数字、日期、人名、引文疑似有误
- 术语用词前后不一致，但不清楚哪个才是标准写法
- 语义不清、可能有两种读法的句子
- 原文的情绪或态度自相矛盾

## 六、声音校准（用户提供样本时）

有作者本人的写作样本时，样本优先于本 skill 的所有词表建议。读样本时记这几项：

- 句长节奏：爱写短句还是长句，长短怎么交替
- 段落长度与分段习惯
- 连接词习惯：用不用「因此」「但是」，还是直接接下一句
- 确定性表达：爱用「可能」「大概」，还是直接断言
- 开篇方式：直接进主题还是先铺垫
- 标点习惯：破折号、括号、分号的使用频率
- 口癖与禁忌词：常用的固定说法，以及从不出现的词

样本和规则冲突时，听样本。改完读一遍，像不像这个人在说话。

## 七、可交付的三种模式

- **粘贴一段文字**：给终稿 + 几行改动说明，不复述全文。
- **文件**：用 patch 改，给 diff 或改动小节，不静默覆盖；只改散文。
- **嵌入场景**（改自己正在写的文档）：默认不解释，直接给改好的版本；用户问起再说明。
